# まちめし 1.5.4

提供された1.5.1の決済機能を引き継ぎ、引継ぎ機能に加えて、テーブル固定が顧客注文画面への切替後にも適用されるよう修正しました。起動時は顧客画面です。「スタッフ端末」を既定1回タップし、初期パスワード `secret` で入ります。使用前にスタッフ設定で変更してください。

## 配布物

- `machimeshi-1_5_4.xdc`：DeltaChat用の更新版。
- 'machimeshi.html': html形式マニュアルです。
  
## 据置き端末のテーブル番号

スタッフの「設定・データ引継ぎ」→「この端末のテーブル設定」で固定をオンにし、番号・名前を入力して保存します。この端末のスタッフ受付・顧客注文画面では同じ番号を使い、連続注文や再起動後も保持します。固定をオフにして保存すると注文ごとの入力に戻ります。オーダー端末へ切り替えても固定表示し、再起動後も保持します。過去の注文は変更しません。

初期パスワードは新規利用時に `secret` です。すでに端末で保存したパスワードは維持します。

## 引継ぎ機能

注文・状態変更・会計履歴・開催情報・メニュー・店舗QR・決済リンクをJSONにまとめます。送信確認待ちの履歴も含みます。取込み前に件数を確認し、開催・決済設定を移すか、移行先の設定を維持するか選べます。既存注文は削除せず、同じ履歴IDは重複させません。内容が異なる同一IDは取込みを中止します。

テーブル固定設定・タップ回数と通知音のオン・オフ／音量は任意で移せます。スタッフのパスワードは書き出さず、移行先の値を維持します。顧客の呼出し先は、端末交代時に限り任意で復元できます。移行元の顧客利用を終了し、移行先1台に復元してください。移行先に未完了の顧客注文がある場合、別の呼出し先には切り替えられません。

新しい引継ぎパックは本番用とデモ用を区別し、相互の取込みを防ぎます。従来形式の注文JSONにはこの区別がないため、デモの旧形式JSONを本番に取り込まないでください。上限は8MiB・30,000履歴です。統合後に上限を超える場合や保存容量不足では取込みを中止します。

同じチャットの同じ1件のwebxdcを使うスタッフ間は、通常は履歴が共有されるためファイル移行は不要です。別のxdc投稿・別のチャット・新版のアプリでは引継ぎ操作を行います。取込み後の共有は送信確認待ちになる場合があり、相手端末でも確認してください。移行前のアプリとバックアップは確認が終わるまで残します。

## 決済・通知音

現金、PayPay、au PAY、楽天ペイ、d払い、外部バーコード決済、Stripe、Squareの8種類に対応します。店舗QRや固定の決済リンクを案内し、実際の入金はスタッフがサービス側で確認して記録します。リンク案内済みは未払いに含まれます。自動請求・自動入金確認・自動返金・注文金額のURL自動設定はありません。

新規注文音はスタッフ画面、受渡し音はスタッフ画面と対象の顧客端末で鳴ります。音を有効化してアプリを開いたまま使います。起動時の履歴再生や引継ぎでは過去の通知音を鳴らしません。閉じたアプリやバックグラウンドでの通知音は保証しません。

デモは単一HTMLを開いて操作します。スタッフ入口は1回、初期パスワードは `secret`。A-102のStripe注文から模擬決済を試せます。模擬成功後もスタッフによる支払確認が必要です。デモの保存先は `machimeshi-demo154-` で始まる名前で分離しています。

注文や決済リンクを含むバックアップはスタッフ間で保管してください。新形式パックは旧版へ直接読み込めません。互換用に「従来形式の注文JSON」の書出しを残していますが、端末設定・呼出し先の指定は新しい引継ぎ画面で扱います。
